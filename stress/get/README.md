# GET больших ответов

```bash
python3 stress/get/server.py --host 127.0.0.1 --port 9000 --size-mb 8 \
  --backend-url http://127.0.0.1:9000
```

Запустите приложение с `PROXY_UPSTREAM=http://127.0.0.1:9000`.
Генератор строит HTML по целым строкам, поэтому размер близок к 8 МиБ,
но не обязательно ровно 8 × 1024 × 1024 байт. Без `--size-mb 8` получается 1 МиБ.

Исходный `getRootNav2 (500 rps)_.jmx` фактически использует 20 потоков и таймер
18000 запросов/мин, то есть **300 rps**. Название и комментарии не являются
фактическими параметрами. HOST/PORT/RPS из его User Defined Variables не связаны
с HTTP sampler и таймером. Для воспроизводимого запуска используйте обёртку:

```bash
python3 stress/get/run.py --url http://127.0.0.1:8080/proxy \
  --reference-url http://127.0.0.1:9000/ \
  --jmeter /workspace/.setup/tools/apache-jmeter-5.6.3/bin/jmeter \
  --threads 20 --ramp 2 --duration 25 --output /tmp/get-run-1
```

Для JMeter задайте `JAVA_HOME` с полноценным JDK 21. В подготовленной облачной
среде это `/workspace/.setup/tools/jdk-21.0.9+10`. В другой среде можно использовать
`--jmeter jmeter`, если JMeter 5.6.3 находится в PATH.

`run.py` создаёт копию исходного JMX в **новом** output-каталоге, подставляет
реальные host/port/path, число потоков, разгон и длительность. Таймер 300 rps
сохраняется: результаты около этого предела не измеряют максимальную пропускную
способность. Путь запрашивается с `?q=UUID`, как в исходном плане.

Перед нагрузкой и после неё сравниваются размер и SHA-256 трёх ответов прокси
с прямым ответом upstream. Во время нагрузки assertion проверяет размер каждого
ответа; полный SHA-256 каждого ответа в измеряемой фазе не вычисляется, чтобы
эта работа на генераторе не подменяла измерение прокси. Код возврата ненулевой
при несовпадении данных, HTTP-ошибках, проваленных assertions или пустом JTL.

В каталоге результата сохраняются `plan.jmx`, `results.jtl`, логи и `results.json`
с размером/hash тела, параметрами, rps, mean/p95 и числом запросов. На Linux
`--proxy-pid <PID Java>` дополнительно считает CPU процесса прокси и мс CPU/запрос.
Для каждого повторения нужен отдельный output-каталог.

Для сравнения версий сохраните собранные JAR в отдельных файлах **вне build/**
и запускайте их на разных портах с одинаковыми параметрами JVM. Не пересобирайте
JAR по пути работающего процесса: лениво загружаемые классы могут стать недоступны.
Прогрейте обе версии, затем чередуйте прогоны A/B/A/B без параллельных сборок и
другой нагрузки. Не сравнивайте изменение только rps: смотрите CPU/запрос, ошибки
и задержки. При запуске всех компонентов на одной машине CPU/сеть общие.

Изменённые настройки по умолчанию: `chunk-bytes=65536`, `io-threads=2`, очередь
ответа 256 КиБ. Для сравнения при старом размере порции используйте
`--proxy.chunk-bytes=16384`; для проверки числа I/O-потоков — `--proxy.io-threads=10`.
Увеличение числа потоков само по себе не сокращает число операций на байт.

## Проверенный результат

2026-10-21, общая машина с квотой 4 CPU и 32 GiB RAM, Temurin 21.0.9,
`-Xms256m -Xmx1g`, JMeter 5.6.3, 20 потоков, 25 секунд и разгон 2 секунды.
Обе версии используют 2 I/O-потока; сравниваются исходные defaults и изменённые.
Исходная версия прогрета предыдущими прогонами; для финального JAR отдельно
выполнен 10-секундный прогрев, затем A/B/A/B. JAR запущены из отдельных копий.

| Показатель | До изменения | После изменения |
| --- | ---: | ---: |
| GET rps (два прогона суммарно) | 150,8 | 188,4 |
| CPU прокси, мс/запрос | 9,61 | 6,88 |
| p95, мс | 204 | 154 |
| Запросов | 7537 | 9419 |
| Ошибок | 0 | 0 |

Размер тела — 8 388 364 байта. SHA-256 до/после каждого прогона совпал с upstream;
размер проверялся в каждом измеряемом запросе. Оба варианта работают с тем же
генератором HTML, без разбора/переписывания тела в прокси. Результат относится к
этому общему стенду, а не устанавливает предельную производительность на другом
оборудовании. Полные условия, SHA-256 JAR, отдельные прогоны и агрегаты сохранены
в [`results.json`](results.json).
После этого замера дополнительно сохранён немедленный flush для группы чтения
только с заголовками, без тела; исправление проверено новым регрессионным тестом.
SHA-256 в результатах относится к измеренному JAR до этого уточнения, а не к
последующей пересборке. Итоговая сборка проходит 245 тестов.
